# CodeQL scanning

## Switch from default setup (administrator action)

The generated default-setup run [46123053850](https://github.com/unsubstantiation/OfflineOTP/actions/runs/46123053850)
failed in Java/Kotlin **Autobuild**; Python, Rust and Actions analysis passed.
The check annotation says automatic compilation failed and requests manual build
steps. Full build logs were inaccessible from this environment, so the underlying
compiler/dependency error is not established.

`.github/workflows/codeql.yml` replaces automatic build discovery with explicit
Java 17/Android SDK 36 provisioning and traced Android/desktop Kotlin compilation.
It does not suppress compiler errors or drop Kotlin analysis. Python, Rust and
Actions retain buildless analysis. Apple-specific Kotlin sources are not compiled
by this Linux scan; keep native iOS validation separate.

Before using this workflow, a repository administrator must turn off CodeQL
**default setup** under **Settings → Code security → Code scanning → CodeQL analysis**
and use advanced setup (the checked-in workflow). Default setup is generated by
GitHub, not stored in this repository, and can conflict with advanced SARIF uploads.
The integration returned HTTP 403 for default-setup settings; no setting was changed.

Once the workflow is on the default branch, run **CodeQL** manually or open a PR
against `master`. Confirm all four analysis jobs pass and appear in code scanning.
The Java/Kotlin job intentionally disables Gradle build-cache reuse and reruns
compile tasks so CodeQL observes compilation. It builds both Android flavors and
the shared desktop presentation sources without packaging or signing releases.
This configuration still needs a successful GitHub-hosted run; local source/YAML
tests are not a successful CodeQL scan.
