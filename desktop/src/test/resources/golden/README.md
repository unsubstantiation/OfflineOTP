# Golden interop blobs

Fixed-vector files that pin the on-disk formats shared by the Android app and the desktop client.
`GoldenInteropTest` hashes every file and opens each blob through the real desktop storage stack,
so a silent change to the codecs, the PBKDF2 split or the byte framing fails the build.

All blobs use the password `golden-interop-password` and the same two-entry vault document
(`expected-vault.json`, produced by the shared `VaultJson` encoder): a 6-digit SHA1 TOTP for
`Golden Issuer` and an 8-digit SHA256 HOTP (counter 9) for `Counter Service`.

| File | Format | Fixed parameters |
| --- | --- | --- |
| `secrets.dat` | nonce-prefixed AES-GCM over the vault JSON | PBKDF2 salt `00..0f`, 4096 iterations; GCM nonce `10..1b`; key = lower PBKDF2 half |
| `vault.properties` | desktop settings for the vault | Base64 URL-safe verifier (upper PBKDF2 half) and salt, iteration count 4096 |
| `otp_accounts.json.aes` | `4-byte BE iterations ‖ 12-byte salt ‖ 12-byte nonce ‖ GCM ct ‖ 16-byte tag` | 140000 iterations, salt `20..2b`, nonce `30..3b` |
| `legacy-otp_accounts.json.aes` | headerless nonce-prefixed AES-GCM, key = SHA-256(password) | nonce `40..4b` |
| `expected-vault.json` | compact `VaultJson` document | plaintext shared by all three encrypted blobs |

## Regeneration

The checked-in generator is `scripts/packaging/GoldenFixturesGenerator.kt`, driven by
`scripts/packaging/generate-golden-fixtures.sh`. It compiles against the sandbox-built `:core`
output (`reports/kotlin-sandbox/desktop/core`) and the Kotlin stdlib, calling only
`CryptoPrimitives` and the same byte framing the codecs use, with the fixed salts/nonces above
instead of random bytes. `vault.properties` has its `Properties.store` timestamp comments stripped
so the file is deterministic.

```
scripts/kotlin-sandbox/compile-desktop.sh      # builds the :core output the generator uses
scripts/packaging/generate-golden-fixtures.sh  # fails if regenerated bytes drift from the fixtures
```

The default run verifies byte-identical regeneration and never touches this directory; pass
`--write` to replace the fixtures after an intentional format change, then update the SHA-256 pins
in `GoldenInteropTest.expectedHashes`.

`desktop-export.json.aes` is a separate, nondeterministic sample produced by the actual desktop
`BackupCoordinator.encryptedBackup` from `expected-vault.json` using the same test password. Its
random salt and nonce are pinned rather than regenerated by the fixed-vector generator. The Android
instrumentation test consumes this exact desktop export, along with the current and legacy fixed
vectors. `desktop-note-export.json.aes` is another actual desktop export containing those two OTPs
and a multiline Unicode note titled `Recovery`; it uses the same throwaway password. These Android
tests must still be run on a device or emulator to verify that runtime.
`desktop-ssh-export.json.aes` is an actual desktop export containing both fake SSH key fields
(the private field exceeds 5 KiB) and those same OTPs. All keys in these fixtures are test data.

`desktop-privacy-export.json.aes` is a desktop-produced mixed OTP, note and SSH backup with
both hidden and revealed entries. Android device restore coverage is compiled but still needs execution.

These are test-only fixtures with a throwaway password and no real accounts.
